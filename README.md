# Deck para SURA — cómo presentarlo

**Abrir:** doble clic en `index.html`. No necesita internet ni servidor: las fuentes y las
capturas están en la carpeta. (Probado con la red apagada.)

**Navegar:** `→` / espacio / clic = avanzar · `←` = volver · `Home` / `End` = primera / última.
Abajo a la derecha está el contador de pantalla; `#/6` en la URL salta a la 7ª.

**Para mandarlo por correo:** `Ctrl+P` → *Guardar como PDF* (una pantalla por página, ya está
configurado). También hay `sura-deck.pdf` generado.

## Lo que NO se dice

- **Nada de RUNT integrado** ni “cumplimiento certificado”. El posicionamiento es *recordamos,
  no certificamos*: es lo que protege a SURA y a nosotros.
- **No prometer SOAT = sin cobertura** con esa contundencia; decir “complica el recobro”.
- **No inventar cifras de siniestralidad.** Si preguntan números: “eso lo medimos con sus datos
  en el piloto”.
- **El canal a SURA hoy es un CSV** (lo muestra la pantalla 6: *Exportar CSV (SURA)*). El envío
  automático por correo/WhatsApp es una integración de ~2 semanas. No mostrarlo como hecho.
- **“Iglu” es nombre interno de código.** Comercialmente es **SureTripCar**.

## Si hay preguntas

- **“¿Ya lo usa alguien?”** → Está corriendo con datos reales (el piloto define la escala).
- **“¿Cuánto cuesta?”** → Por vehículo/mes; el piloto no tiene costo. Una RTM vencida
  (≈$875.000 + inmovilización) paga años de plataforma en una flota de 50 vehículos.
- **“¿Y el GPS que ya tenemos?”** → No competimos: el GPS no sabe de vencimientos ni mira al
  conductor. Podemos leer la posición desde su proveedor actual.
